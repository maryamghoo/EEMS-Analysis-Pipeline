# EEMS analysis

This repository contains scripts to prepare SNP data and run Estimated Effective Migration Surfaces (EEMS) on a SLURM cluster.

## Software

- **EEMS:** `runeems_snps` (SNP implementation), source commit `34ebbb6` (2023-10-28; local working tree marked `dirty`)
- **PLINK:** v1.90b6.16, 64-bit (19 Feb 2020)
- **Other requirements:** Bash, SLURM, and the EEMS `bed2diffs_v2` utility

## SNP data

Use a quality-filtered set of LD-pruned biallelic nuclear SNPs from the non-closely-related individuals included in the study.

The supplied script uses `bed2diffs_v2`, which replaces missing genotypes with the SNP's mean genotype when calculating dissimilarities. This can be problematic if missingness is nonrandom. The upstream EEMS documentation recommends careful filtering of SNPs with high missingness and then using `bed2diffs_v1`; record which method is used and consider sensitivity analysis if missingness remains. See the [bed2diffs documentation](https://github.com/dipetkov/eems/tree/master/bed2diffs).

## Input files

| File | Description |
| --- | --- |
| `filtered_snps.vcf` | Filtered, preferably LD-pruned SNP genotypes |
| `samples.keep` | Two columns: PLINK family ID (FID) and individual ID (IID), no header |
| `eems_data.coord` | Longitude and latitude, one individual per line, **in the order of `eems_data.order`** |
| `eems_data.outer` | Study-area boundary; polygon vertices in counterclockwise order, first vertex repeated at the end |

The coordinate and boundary files must be placed in `PROJECT_DIR` before the preparation job finishes. The script checks that the coordinate file has the correct number of lines, but **does not check that coordinates belong to the correct individuals**. Verify the order manually against the `.fam` or `.order` file.

### Creating `eems_data.outer`

The `.outer` file is prepared separately; PLINK and EEMS do not create it. It defines the geographic boundary of the habitat used in the analysis. You can use [GEOLocate](https://www.geo-locate.org/) to find locality coordinates or sketch a polygon, then prepare the EEMS file from its vertices. GEOLocate does not export an EEMS-ready `.outer` file directly.

Save the boundary as a plain-text file with **longitude and latitude** (decimal degrees), separated by spaces, with no header. List polygon vertices **counterclockwise**, repeat the first point at the end, and make sure the boundary contains all sampling locations and reflects the study habitat.

Example `eems_data.outer`:

```text
-81.5 27.5
-80.5 27.5
-80.5 29.0
-81.5 29.0
-81.5 27.5
```

Place `eems_data.outer` in `PROJECT_DIR` before running the preparation job. The coordinates above are only an example; use the boundary appropriate for your study.

## 1. Prepare the data

Edit the paths at the top of `01_prepare.sh`:

```bash
PROJECT_DIR="/path/to/eems_project"
VCF="/path/to/filtered_snps.vcf"
KEEP="/path/to/samples.keep"
BED2DIFFS="/path/to/eems/bed2diffs/src/bed2diffs_v2"
```

Update the SLURM partition and resources for your cluster, then submit:

```bash
sbatch 01_prepare.sh
```

This job:

1. Uses PLINK to retain the requested samples and write `snps.bed`, `snps.bim`, and `snps.fam`.
2. Writes `eems_data.dist` and `eems_data.dist.id` for reference (`.dist` is **not** the matrix used by EEMS).
3. Runs `bed2diffs_v2` and writes `eems_data.diffs` and `eems_data.order`.
4. Checks that `eems_data.coord` and `eems_data.outer` exist, and checks the number of coordinate rows.
5. Creates `PROJECT_DIR/params.ini` with the actual sample and SNP counts.

The generated `params.ini` uses `nDemes = 200`, `numMCMCIter = 20000000`, `numBurnIter = 2000000`, and `numThinIter = 10000`. The script calculates `nIndiv` and `nSites` from the PLINK files. The EEMS SNP implementation defaults to diploid genotypes; confirm that this matches the dataset.

**Note:** `01_prepare.sh` overwrites `PROJECT_DIR/params.ini`. The separately supplied example `params.ini` is only a template: its `./data/eems_data` path and `nSites = 100000` placeholder do not match the files generated by this script. Edit the generated parameter file if you need different MCMC settings.

## 2. Run EEMS

Once the preparation job has completed successfully, edit the paths in `02_run_eems.sh`:

```bash
PROJECT_DIR="/path/to/eems_project"
EEMS="/path/to/eems/runeems_snps/src/runeems_snps"
```

Submit the run:

```bash
sbatch 02_run_eems.sh
```

The script runs `runeems_snps` using the generated `params.ini` and random seed `123`. Its SLURM settings request 32 CPUs, 64 GB RAM, and up to five days; adjust them if necessary. It will stop if `PROJECT_DIR/output` already contains files, to avoid mixing runs.

## Outputs

| File or directory | Description |
| --- | --- |
| `snps.bed`, `snps.bim`, `snps.fam` | PLINK genotype files |
| `eems_data.dist`, `eems_data.dist.id` | PLINK distance matrix and individual IDs, for reference |
| `eems_data.diffs` | Pairwise genetic dissimilarities used by EEMS |
| `eems_data.order` | Individual order for the dissimilarity matrix |
| `params.ini` | Generated EEMS run settings |
| `output/` | EEMS MCMC output files |
| `prepare_<jobid>.out/.err`, `eems_<jobid>.out/.err` | SLURM standard output/error logs (in the submission directory) |

## 3. R plots and diagnostics

Use `EEMS_plots.R` to plot EEMS results in R. The script uses `reemsplots2` for the EEMS surfaces and diagnostics, with `ggplot2`, `sf`, `rnaturalearth`, `ggspatial`, and `ggrepel` for geographic maps.

Install the packages once in R:

```r
install.packages(c("remotes", "ggplot2", "sf", "rnaturalearth", "ggspatial", "ggrepel"))
remotes::install_github("dipetkov/reemsplots2")
```

Run the plotting script locally in R or RStudio. Set the working directory to the project folder containing the EEMS `output/` directory (copy the EEMS results from the cluster to your computer first). Check the working directory with `getwd()`.

At the top of `EEMS_plots.R`, use:

```r
r_input <- file.path(getwd(), "output")
r_output <- file.path(getwd(), "plots")
```

`r_input` contains the EEMS output files from `02_run_eems.sh`. The script looks for `eems_data.outer` and `eems_data.coord` in the working directory. If `sample_coordinates.csv` is available there, it uses that file for sampling points and optional `Location` labels and `Region` colors; otherwise, it uses `eems_data.coord`. The CSV needs `Longitude` and `Latitude` columns. Geographic maps use Natural Earth ocean polygons, which require internet access when downloaded.

The script creates `r_output` and saves:

- Standard EEMS plots (`mrates01`, `mrates02`, `qrates01`, `qrates02`, `rdist01`–`rdist03`, and `pilogl01`) as PNG and PDF.
- Migration and diversity maps (`mrates01_map`, `mrates02_map`, `qrates01_map`, and `qrates02_map`) as PNG, PDF, and SVG.

Before interpreting the maps, check MCMC mixing, agreement across independent chains, and model fit. The current SLURM script runs **one** chain with seed `123`; a single completed run does not establish convergence.
